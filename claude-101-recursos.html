Documentación oficial

RecursoQué encuentras ahíPor qué vale la pena
Models overview Modelos vigentes, IDs exactos, context window, max output, knowledge cutoff. Es la única fuente que no envejece mal: los IDs cambian y los deprecados rompen código en producción.
Tool use El ciclo tool_use / tool_result, client vs server tools, tool_choice, paralelismo. Ese ciclo es literalmente el corazón de un agente. Sin esto, "agente" es una palabra de marketing.
Agent Skills SKILL.md, scripts asociados y divulgación progresiva en tres niveles. Es la forma de empaquetar un workflow tuyo para que sea reutilizable y no viva en un archivo de notas.
Claude Code — overview Todas las superficies: CLI, VS Code, JetBrains, escritorio, web y móvil, con el mismo motor y la misma configuración. Aclara que no son productos distintos: son entradas distintas al mismo agente.
MCP en Claude Code Transportes, alcances local/project/user y las advertencias de seguridad. Es donde vas a configurar MCP de verdad, y donde está escrito el riesgo de prompt injection.
CLAUDE.md y auto memory Cómo se escribe el archivo que se lee al inicio de cada sesión y qué se guarda entre sesiones. Es el mayor retorno por línea escrita: un buen CLAUDE.md ahorra contexto en cada prompt del semestre.
Hooks Comandos de shell antes o después de acciones del agente. Convierte tu disciplina en automatización: formatear tras cada edición, pasar lint antes de commit.
Subagents Varios agentes en paralelo sobre partes distintas de una tarea, con un líder que coordina. Es el paso de "un agente que hace" a "un equipo que reparte", y cambia cómo divides el trabajo.
Best practices Recomendaciones de uso del agente en repos reales. Lo más corto de leer y lo que más rápido se nota en tu velocidad al día siguiente.
Projects Knowledge, project instructions, RAG al acercarse al límite del context window, permisos en Team/Enterprise. Explica con precisión qué es el modo RAG del Project y por qué no es lo mismo que subir un PDF al chat.
Claude Code en la web La superficie web del agente, en claude.ai/code. Sirve para arrancar una sesión sin terminal y luego traerla a tu máquina con claude --teleport.

Especificaciones

RecursoQué encuentras ahíPor qué vale la pena
Especificación MCP 2026-07-28 Modelo stateless de request/response, multi round-trip requests, routing por headers, listas de tools cacheables con TTL, auth más fuerte, framework de extensiones. Es el estándar que hoy respaldan públicamente Google Cloud y Microsoft (Foundry). Leer una spec completa es un ejercicio de ingeniería en sí mismo.
Build an MCP server Guía paso a paso para exponer tools, resources y prompts desde un servidor propio. Escribir un servidor de tres tools es la forma más rápida de entender qué es y qué no es un agente.

Lectura crítica

RecursoQué encuentras ahíPor qué vale la pena
METR (2025), Measuring the Impact of Early-2025 AI on Experienced Open-Source Developer Productivity — arXiv:2507.09089 RCT con desarrolladores open source experimentados en tareas reales de sus propios repos: fueron ~19% más lentos con herramientas de IA mientras creían ir ~20% más rápido. Es el dato más honesto que existe sobre la brecha entre percepción y realidad. Léelo con sus límites: expertos, repos que ya conocían muy bien, herramientas de principios de 2025.
El mismo estudio, versión divulgativa Resumen del diseño experimental y de los resultados, con gráficas. Es la versión que puedes citar en una discusión de equipo sin pedirle a nadie que lea un paper.
Andrej Karpathy, post original sobre vibe coding (febrero de 2025) — buscar la fuente original La definición inicial: dejarse llevar, aceptar el código sin revisarlo, "olvidar que el código existe". Vale leer la formulación original antes de opinar sobre el término, porque casi todo lo que se cita después es paráfrasis de paráfrasis.
Críticas de seguridad al vibe coding (Cloud Security Alliance, prensa 2025–2026) — buscar la fuente original Argumentos sobre vulnerabilidades y deuda técnica en flujos con poca supervisión. Útil como contrapeso, pero las cifras que circulan vienen de organizaciones interesadas o de prensa, no de estudios revisados por pares: trátalas como afirmaciones a verificar.

Práctica

RecursoQué encuentras ahíPor qué vale la pena
Instalar el CLI y abrir campusflow-api Los comandos de instalación y el arranque de sesión en un repo. Nada de esto se aprende leyendo. El primer claude dentro de tu propio repo cambia la conversación.
Escribir tu propio CLAUDE.md Estándares del repo, decisiones de arquitectura, librerías preferidas, checklist de revisión. Es la práctica con mejor relación esfuerzo/beneficio de toda la lista.
Construir un servidor MCP mínimo Un servidor con dos o tres tools sobre datos tuyos, conectado con claude mcp add. Cierra el círculo entre el ciclo tool_use de la API y lo que ves en tu terminal.
Implementar el ciclo de tool use a mano Una llamada a la API con tools, manejo de stop_reason: "tool_use" y devolución de tool_result. Después de escribirlo una vez, ningún framework de agentes te va a parecer magia.

Qué hacer las dos semanas siguientes

Plan realista: 4 a 6 horas por semana. No es una lista de deseos, es lo que cabe.

SemanaLeer (~2 h)Construir (~3 h)Verificar
Semana 1 — fundamentos y repo Models overview, Claude Code overview, best practices y memory. Instala el CLI, abre tu propio repo, escribe un CLAUDE.md de 30–40 líneas y arregla con él un bug real con su test de regresión. El test falla antes del fix y pasa después. Tú puedes explicar el diff línea por línea sin volver a abrir el chat.
Semana 2 — tools, MCP y criterio Tool use, MCP en Claude Code, la spec 2026-07-28 y el estudio METR. Escribe un servidor MCP con dos tools sobre datos tuyos siguiendo build-server, conéctalo con claude mcp add y agrega un hook que pase lint antes de commit. claude mcp list y /mcp muestran el servidor arriba; el hook bloquea un commit sucio; anotaste qué tarea de la semana fue más lenta con IA que sin ella.

Cuidado

Si conectas un servidor MCP que trae contenido externo, quedas expuesto a prompt injection. Conecta solo servidores en los que confías y usa credenciales de solo lectura cuando puedas.

Don't just use AI. Learn to engineer with AI.
